# AgentSOC — Demo Guide

Verified dataset → Phase 2 detection → incident → Investigator Agent (Groq LLM or
deterministic fallback) → Streamlit SOC dashboard.

## 1. Environment setup (once)

```powershell
cd C:\Users\pramo\OneDrive\Desktop\AgentSOC-Final_Year\AgentSOC
python -m venv .venv                      # skip if .venv already exists
.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
pip install -e . --no-deps
```

`.env` (not committed) must contain:

```
LLM_PROVIDER=groq
GROQ_API_KEY=gsk_...            # your Groq key
GROQ_MODEL=openai/gpt-oss-120b  # a model your account can use
LLM_MAX_TOKENS=4000
```

**Important on this PC:** an old `GROQ_API_KEY` is set at Windows *machine* level and overrides
`.env`. Remove it once in an **Administrator** PowerShell, then restart VS Code / the terminal:

```powershell
[Environment]::SetEnvironmentVariable('GROQ_API_KEY', $null, 'Machine')
```

Check: `python scripts/check_environment.py` → `[ OK ] configured model 'openai/gpt-oss-120b' is available`.
If you cannot remove it, the dashboard still works — it shows a warning and uses the fallback.

## 2. Dependencies

Python 3.11+, packages pinned in `requirements.txt` (pandas, pydantic, openai, streamlit, plotly, …).
No other services. Network is needed only for live Groq calls.

## 4. Synthetic scenario (default)

The default source **"Synthetic demo scenario (4 days)"** is built automatically on first launch
from `data/samples/auth_scenarios_synthetic.txt` with the existing Phase 1/2 pipeline (into
`data/processed/demo/`). Expected: 3 incidents — alice.fin **CRITICAL**, carol.fin **MEDIUM**,
dave.it **LOW** (admin); bob.hr and erin.ops none; 15 detections.

LANL validation runs (real, sampled data) appear as extra sources if
`data/processed/lanl_validation/` exists.

## 5. Investigate an incident

1. Sidebar → **Selected incident**: `INC-00002 · alice.fin@CORP · CRITICAL` (default).
2. **Incident details** tab: timeline, rules, severity rationale, benign explanations, missing info.
3. **Evidence** tab: the actual normalised events (raw file + line for each).
4. **AI investigation** tab → **Investigate with AI**. A saved result (if any) is shown first;
   the button re-runs it. The badge says **Generated by Groq LLM · model** or
   **Generated by deterministic fallback**.

Saved results are real outputs of earlier runs (stored in
`data/processed/demo/detection/investigations/`, tied to the incident's SHA-256).

## 6. How fallback works

The LLM is used only when the button is clicked. If Groq times out, rate-limits, rejects the key,
is unreachable, or returns output that fails validation twice (e.g. cites an event that is not
in the incident), the **deterministic fallback** produces the same structured result from the
detection rules, and the dashboard shows why. To demonstrate: sidebar → **Simulate LLM outage
(demo)** (no request is sent), or **Mode → Deterministic fallback only**.

## 7. Demonstration script (~5 min)

1. **Overview** — 3 incidents, severity mix, 15 detections; point at the yellow
   *SYNTHETIC demonstration data* banner.
2. **Incident explorer** — filter/search; click Alice's row.
3. **Incident details** — failures on unfamiliar WS-FIN-07 → success → WS-FIN-07 → SRV-APP-02 →
   DB-FIN-01; severity calculation; benign explanations; missing information.
4. **Evidence** — 9 real normalised events with source line numbers. Nothing is generated.
5. **AI investigation** — click **Investigate with AI** (5–20 s live). Show provider badge,
   competing hypotheses and confidence chart, supporting/contradicting events with "why it
   matters", ATT&CK links, next steps, evidence gaps, and the *not proof of compromise* note.
6. Select **Carol** → investigate → benign forgotten-password explanation ranks first.
7. Toggle **Simulate LLM outage** → investigate → orange *deterministic fallback* badge and the
   outage warning: the workflow still completes.
8. **Provenance** — manifest and detection hashes; switch source to a LANL run to show real data
   (blue banner).

## 8. What is and is not demonstrated

| Demonstrated | Not demonstrated |
|---|---|
| Verified ingestion, 7 detection rules, correlation, evidence integrity | Graph feasibility (SSE, Phase 4) |
| LLM investigation with schema + evidence grounding, repair round, fallback | Risk scoring / action ranking (RSEM, Phase 5) |
| Prompt-injection handling (data-block isolation, flagging, grounding) | Response actions, approval workflow, audit trail (Phase 7) |
| Synthetic vs real (LANL) provenance in every view | Real-world detection accuracy (synthetic results do not measure it) |

Confidence values are investigative estimates, not probabilities. LANL authentication logs
contain no malware/PowerShell/endpoint data and none is shown. The paper's reported 506 ms is
the paper's result, not ours (our Groq investigations took 4–19 s).
